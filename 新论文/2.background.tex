\section{Background and Problem Formulation}
\label{sec:background}

Error-bounded lossy compression and configuration tuning provide the two foundations of ASZ. This section reviews data-adaptive compression in database systems and error-bounded lossy compression, then formulates the compression and precompression-tuning objectives considered in this work.

\subsection{Data-Adaptive Compression in Database Systems}
\label{sec:background:database}

Compression has long been integrated into database systems to reduce storage requirements while supporting efficient access to compressed data~\cite{li1987compression}. In modern data-management platforms, BtrBlocks~\cite{kuschewski2023btrblocks} and ALP~\cite{afroozeh2023alp} provide lossless compression for columnar storage in data lakes and floating-point columns in analytical systems, respectively. Both adapt their compression methods to data characteristics instead of applying one representation uniformly. ASZ also targets data-management systems, providing error-bounded lossy compression for multidimensional scientific fields.

\subsection{Error-Bounded Lossy Compression}
\label{sec:background:compression}

Error-bounded lossy compression supports scientific data management by reducing storage requirements and data movement through I/O and network transfers while controlling reconstruction error~\cite{cappello2019use,di2025survey}. Existing compressors mainly follow prediction-based or transform-based designs.

Prediction-based compressors such as SZ3~\cite{zhao2021optimizing,liang2022sz3} and QoZ~\cite{liu2022dynamic,liu2024high} often predict each data value as a weighted combination of previously reconstructed neighboring values. They then quantize the prediction errors and losslessly compress the resulting sequence of quantization-bin indices. ASZ also belongs to this class.

Transform-based compressors such as ZFP~\cite{lindstrom2014fixed}, SPERR~\cite{li2023lossy}, and MGARD~\cite{gong2023mgard} use block transforms, wavelets, and multilevel decompositions, respectively.

\subsection{Compression Objective}
\label{sec:background:compression-objective}

We evaluate error-bounded compressors by their rate--distortion performance and runtime. Rate--distortion performance describes how much a compressor reduces the data size at a given reconstruction quality, and runtime describes how long the compressor takes to achieve this reduction. We next formalize these quantities.

Let $X=(x_i)_{i=1}^{N}$ denote a scientific field containing $N$ values, and let $\epsilon_{\mathrm{abs}}>0$ be a user-specified absolute error bound. Compression produces a bitstream for $X$, and decompression reconstructs $\hat X$ from this bitstream. Error-bounded compression requires
\begin{equation}
\label{eq:background:error-bound}
|x_i-\hat x_i|\leq\epsilon_{\mathrm{abs}},\qquad i=1,\ldots,N.
\end{equation}

Compression effectiveness is measured by the compression ratio or the bit rate. Let $B$ be the complete compressed size in bits, and let $b_{\mathrm{ori}}$ be the original number of bits per value. The compression ratio and bit rate are
\begin{equation}
\label{eq:background:rate}
\mathrm{CR}=\frac{Nb_{\mathrm{ori}}}{B},\qquad \mathrm{BR}=\frac{B}{N}.
\end{equation}
For a fixed input representation, these are equivalent measures of data reduction, with $\mathrm{CR}\,\mathrm{BR}=b_{\mathrm{ori}}$.

Reconstruction quality is measured using mean squared reconstruction error (MSE) and peak signal-to-noise ratio (PSNR), with
\begin{equation}
\label{eq:background:quality}
\mathrm{PSNR}=10\log_{10}\frac{R_X^2}{\mathrm{MSE}},
\end{equation}
where $R_X=\max_i x_i-\min_i x_i$ is the original value range of a nonconstant field.

Different compressors or configurations can achieve different PSNR values under the same error bound because they produce different distributions of reconstruction errors. Varying the error bound produces a rate--distortion curve that shows the trade-off between bit rate and reconstruction quality. We therefore compare bit rates at matched PSNR along these curves rather than compare runs solely by error-bound value.

Runtime can be reported at several scopes. Codec time covers compression and decompression. Total runtime also includes the precompression tuning described in Section~\ref{sec:background:tuning-objective}. \textcolor{red}{End-to-end data-management time further includes network transfer time, which depends on the compressed size and network bandwidth.}

\subsection{Precompression Tuning Objective}
\label{sec:background:tuning-objective}

Precompression tuning is a preprocessing stage that searches among a compressor's available configuration choices for a given input and error bound before compression. The configurable mechanisms implemented by the compressor determine the available configuration space. The objective is to select a configuration with strong rate--distortion performance while keeping the tuning time practical.

Tuning time is accounted for separately from codec time. When tuning is performed for every file, the total runtime of each file includes its full tuning cost. When the selected configuration is reused across related files, the one-time tuning cost is amortized over those files. SZ3 and QoZ run their built-in tuning inside compression, so their measured compression time already includes this cost.
